# Frontend refinement report

Date: 2026-10-07. This pass continued the existing implementation. No Figma MCP calls were made and no replacement assets were downloaded. Visual decisions reuse the extracted Outfit typography, neutral surfaces, blue controls, spacing, radii and shadows. Application composition is based on real Drupal functionality rather than a new marketing or analytics dashboard.

## Findings and changes

| Observed issue | Change |
| --- | --- |
| Front page was `/user/login`; authenticated users were redirected to a sparse `/user/{uid}` profile with little beyond “Member for.” | Added `/projects` as the application landing page and changed both the synchronized and active local `system.site:page.front` to `/projects`. It shows access-checked real project entities, links to their existing boards, and up to eight recently updated tasks assigned to the current user. No projects, tasks, users or statistics were created to populate it. |
| Regular users had no useful application navigation. | Added Projects navigation for all roles. Project creation is shown only when the existing route access result permits it. Anonymous sign-in links carry an application destination. Existing account routes remain intact. |
| Empty sidebar regions left a blank panel. Lazy-rendered menu placeholders initially looked empty even when the administrator had menu access. | Render optional sidebar blocks without automatic placeholders before deciding whether the region is empty. The normal render pipeline retains and bubbles access/cache metadata. Regular/anonymous users have no empty panel; administrators retain their real Tools/Administration menu. |
| Revision and authoring headers were crowded in core vertical tabs; mobile details had little visual separation. | Added a dedicated form-details component stylesheet: spaced tab titles/summaries, selected states, padded panes, bordered native details, consistent focus treatment, and readable expanded/collapsed mobile sections. Core labels, fields, widgets and grouping remain unchanged. |
| Date/time controls, checkbox labels, required markers and file upload buttons looked inconsistent. | Extended shared form styles using existing tokens. Added no new widgets or validation logic. |
| Local task tabs rendered as ordinary bulleted links. | Added a semantic local-tasks template that uses the existing tab component. Navigation links and access are still generated by Drupal. |
| Several field styles had no stable classes in the base-theme-free markup. | Added a field template with stable `field`, label/item and field-name classes, and node classes on the two existing entity templates. All content remains native formatter output. This activates existing task-detail, badge and card styling. |
| Dialogs used core Arial styling, oversized titles and small sprite close buttons. The media chooser used only 75% of the mobile viewport. | Unified dialog font, header, spacing, rounded surfaces, close controls and focus states. The CSS cross decorates the actual core Close button. Task/media widths follow viewport bounds, with internal scrolling only where necessary. No custom modal lifecycle was substituted. |
| A fast modal close followed by resize could leave core's debounced resize callback targeting a removed widget. | Task/media dialogs use synchronous resize updates through Drupal's dialog events and the existing jQuery UI widget. Resize listeners are removed before close; other Drupal dialogs retain their core resize behavior. |
| Administrator frontend-editing hover controls intercepted board title clicks. The iframe drawer controls overlapped its content and lacked labels/focus return. | Moved editing controls away from titles, preserved their actual edit links, added a proper drawer action row, accessible control names, a consistent close icon, mobile sizing, Escape handling including the same-origin iframe, and focus return. Existing editor creation/removal, iframe form, preview and submission behavior remain with the contributed module. |
| Account display used bare core markup. | Added a shared-surface account template/style while retaining the real profile content. |

## Access and data contracts

The landing controller uses dependency injection, access-checked node queries, explicit entity/field/route access results, entity/list cache tags and user/pager cache contexts. Its pager contains real accessible project results. The assigned-task query is limited to the current user's actual `field_assignee` value. Empty projects/tasks have explicit translated states and only permitted actions.

Anonymous users see only public accessible projects and a real sign-in action. Regular users see accessible project/board links and their assigned tasks; they do not acquire administrative or entity-creation permissions. Administrator tools remain accessible and visible. The active local configuration change affects only the front-page key; no bulk configuration import was performed.

No existing status, moderation, CSRF, time-log, media or entity-operation backend contract was replaced. No mock API response, static entity list, placeholder user, chart value or artificial statistic was introduced. The old untracked `docs/frontend-redesign-audit.md` was preserved.

## Browser verification

Playwright inspected existing local application users: anonymous, regular user ID 2, and administrator ID 1. The IDs were discovered from the real installed accounts; no account was created for the visual review.

- Homepage, login and account: all three roles at 1440px, 768px and 375px. Root now remains on the application landing page instead of redirecting signed-in users to a profile. Regular-user project/task creation and project editing remained denied (403).
- Project and task create/edit: all four forms at each width, switching revision/authoring vertical tabs on desktop/tablet and expanding/collapsing native details on mobile.
- Task dialogs: keyboard opening, pointer opening with administrator editing controls enabled, styled Close button, Escape, focus return, mobile sizing, and viewport changes while open.
- Media dialogs: real library opening, navigation/filter controls, close/Escape, desktop/tablet/mobile bounds and scroll containers. Existing media upload/selection tests still pass.
- Editing drawer: board edit action, real iframe form, Close control geometry, Escape from a confirmed focused iframe Title input, and focus return at all three widths.
- Additional route review: project canonical/statistics, task board, task canonical/edit, task creation, project creation, task time logging and time-log collection at all three widths.
- No document overflow, broken downloaded assets, or browser console/page errors in the final reviews. Task/media dialogs had zero or one content scroll container as appropriate; drawer scrolling stays in its iframe.

The final automated suite passed **17/17 tests**: all 14 original tests unchanged, plus two role-based homepage regressions and one keyboard/close/resize dialog regression. This includes normal Save, explicit workflow transitions, required-project validation, project types, board status persistence/project isolation, task/project edits, time logging, permissions, media and Scrum-only sprint access. Tests use the established isolated real-entity fixture lifecycle and cleanup; test data is not part of application presentation.

Other checks passed: Drupal cache rebuild, complete configured PHPCS Drupal/DrupalPractice checks, configured PHPStan, PHP syntax for the new controller/module registration, all theme Twig templates compiled, JavaScript syntax, declared library path existence and `git diff --check`.

Local visual-review artifacts and JSONL results are under `.playwright/frontend-polish/` (ignored workspace artifacts). No existing tests were weakened or changed.
